# ADR-001: Модульный монолит вместо микросервисов

## Статус
Принято

## Контекст
LoVeTeA разрабатывается одним разработчиком / небольшой командой. На старте не нужно оплачивать и поддерживать сложную микросервисную инфраструктуру.

## Решение
Архитектура — модульный монолит: один Go backend, разделённый на независимые бизнес-модули (auth, users, couples, onboarding, moments, calendar, tasks, wellness, habits, chat, memories, location, games, wheel, dates, pet, notifications, sync, account, home, reminders).

## Последствия
- Проще разрабатывать, запускать, тестировать и развёртывать.
- Модули разделены по предметным областям, код не превращается в один большой набор обработчиков.
- При необходимости отдельный модуль можно вынести в сервис позднее.
