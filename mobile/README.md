# LoVeTea Mobile

Flutter-клиент для Android и iOS. Клиент использует REST API Go backend из
`docs/api/openapi.yaml`.

## Запуск

1. Запустите backend и его зависимости по инструкции в корневом `README.md`.
2. Убедитесь, что API доступен на порту `8080`.
3. Из этой папки выполните:

```powershell
flutter pub get
flutter run
```

Для Android Emulator адрес backend по умолчанию — `http://10.0.2.2:8080`.
Для iOS Simulator и Web используется `http://localhost:8080`.

Чтобы указать адрес для физического устройства или другого окружения, передайте
base URL без `/api/v1`:

```powershell
flutter run --dart-define=API_BASE_URL=http://192.168.1.10:8080
```

Устройство должно иметь сетевой доступ к backend; для production используйте
HTTPS.

Чтобы проверить веб-клиент в Chrome, выполните `flutter run -d chrome`.
Перед проверкой убедитесь, что backend доступен по адресу `localhost:8080`.

## Реализованные сценарии

- Регистрация и вход с сохранением access/refresh token в secure storage.
- Восстановление сессии и обновление access token.
- Просмотр аккаунта и изменение имени профиля.
- Состояние питомца пары на главной странице из серверного снимка `/home`.
- Ближайшие задачи, события и важные даты на главной странице из серверных
  списков планирования.
- Drift хранит персональный sync-курсор и полученные изменения с версиями и
  tombstone; синхронизация pull запускается с главной страницы.
- Создание приглашения пары с QR-кодом и копированием одноразового
  кода/токена; присоединение по коду или сканированием QR-кода.
- Подтверждение отвязки пары с явным согласием обоих участников.
- Главная страница и нижняя навигация.
- Личные/общие задачи со сроком, календарные события и важные даты; просмотр
  списком, по неделе и по месяцу.
- Привычки, отметки выполнения и серверная статистика недельных серий.
- Приватные отметки настроения и сна с отдельным согласием на показ партнёру
  и недельной сводкой только собственных записей.
- Опубликованные onboarding-тесты и сохранение личных ответов.
- Личные и общие моменты с датой, заметкой и фотографиями JPEG/PNG (до 20 МиБ
  каждая); загрузка и просмотр используют краткоживущие URL backend.

Серверные функции без поддерживаемого или ещё не подключённого клиентского
сценария (например, чат и push) здесь не подменяются локальными
демонстрационными данными. Для сканирования QR в браузере нужна камера и
защищённое соединение (HTTPS или localhost). Для веб-загрузки фотографий
объектное хранилище должно разрешать CORS-запросы от origin веб-клиента.
Состояние питомца на главной странице пока только читается из `/home`:
backend не предоставляет мобильному клиенту API для настройки внешности или
действий питомца. Уведомления для сроков задач также не отправляются.
Офлайн-чтение экранов и постановка пользовательских изменений в sync-outbox
ещё не подключены к этому локальному кэшу.
